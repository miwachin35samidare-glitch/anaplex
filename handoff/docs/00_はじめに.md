## 3. 出どころの印

```
【み】     みわの言葉（言葉のまま、日付つき）
【み選】   Claude が出した案から、みわが選んだ
【み?】    みわが関わったが、言葉か選択かが記録から分からない
【C】      Claude の案・Claude が入れたもの（みわ未確認）
【ヒト】【マカク】【マーモセット】【ラット】【マウス】…  測定の種（値ごと・主張ごとに付ける。人の出典が無いものに「人の」と書かない）
【測】     模型で測った結果（何で・どの版で）
【見】     見立て（確かめていない）
【?】      出どころを記録から確かめられない
```

**【C】【み選】【?】は覆せる。**人に照らして確かめ直す対象。「みわが決めたから」と扱わない。
**過去の判断を持ち出すときは、印を見て言葉のまま引く。**Claude が書いた理由を、みわの判断として言わない（10-01「根幹」の取り違え）。

## 4. 案を出す前に（毎回）

案の部品ごとに、この4つを書いてから出す。1つでも埋まらなければ、案として出さずに「ここが埋まっていない」と言う。

```
1 出どころ     人の測定（種）／ みわの言葉 ／ Claude の案
2 過去         過去スレッド（conversation_search）と論点台帳の「落とした案」、決まったこと.md（project_search）で、同じ論点を引いた結果
3 触る決め     その案が変える・前提にする決めと、その決めの出どころ
4 試したか     最小構成で試したか。試していなければ「試していない」
```

判断を仰ぐときは選択肢を出す。一度に聞くのは1つ。人で決まっていることは選択肢にしない。
発話は人で見る（霊長類の手の記録を持ち込まない【み】09-30）。数値は人で探す【み】10-01。

## 5. 書き方

```
確定した時点で、論点台帳のその論点を書き換える（スレッドの終わりにまとめて書かない）
書き換えは「いまの形」を直し、古い形は「落とした案」へ理由と日付つきで移す
みわの言葉は言葉のまま引用する。Claude の解釈と欄を分ける
01_現在地 はスレッドの区切りで書き換える。事実だけ（版・最後に測ったもの・次の問いとそれが乗っている決め）
  前の現在地は 01_現在地_MMDDまで.md に分けて残す
設計の経緯（人の値・読んだ論文・落とした案）は 設計案_脳幹.md の §12-xx に足す。目次も足す
コードを変えたら babble.py の VERSION を上げ、履歴の行に理由と出どころを書く
arkhe のファイルを直すときは apply_vNN.py（印が1つでも無ければ何も書かずに止まる）。コンテナの写しで当てて確かめてから渡す
```
